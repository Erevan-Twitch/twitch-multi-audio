## What was built

### Repository
- **Monorepo:** `apps/extension`, `apps/server`, `packages/shared` (protocol types), `packages/tsconfig`.
- **Tooling:** pnpm 12 through Corepack, Turbo 2, TypeScript 7, Node 24.
- **Extension stack:** plain Manifest V3 and Chrome APIs, no extension framework. esbuild only bundles the TypeScript ([scripts/build.ts](../../apps/extension/scripts/build.ts)).

### Extension
- **Side panel:** lists identified tabs with cover, title, artist, site and favicon. States: 🔊 playing, ⏸ paused, 🔈 muted in the player, 🔇 muted at the tab level (the tooltip says who muted it).
- **Service worker:** applies the identification rule ("How tabs are identified" in the roadmap) and keeps one record per tab in `chrome.storage.local`, cleared on browser start. It sends the panel a fresh snapshot over a port, and injects the scripts into tabs already open at install or reload.
- **Content script** (isolated world): reads `navigator.mediaSession` and the page's media elements every second, and reports changes.
- **Page-context hook** (`world: "MAIN"`): wraps `HTMLMediaElement.prototype.play` to catch players kept out of the page. Chillhop needed this.

### Tests
- **Manual test cases**, written to be automated later: [01-tab-list.md](../../apps/extension/test/cases/01-tab-list.md) and [02-track-info.md](../../apps/extension/test/cases/02-track-info.md).
- **Controllable test page** ([media-page.html](../../apps/extension/test/fixtures/media-page.html)), served with `pnpm --filter @tma/extension test:fixtures`.

## Problems found and how they were solved

| Problem | Cause | Solution |
| --- | --- | --- |
| Tabs dropped from the list when paused or muted in the player | `Tab.audible` only means "produced sound in the last ~2 s" | `audible` only *adds* a tab; a tab stays until it's closed, moves to another site, or loses its track info |
| List empty after reloading the extension | `storage.session` is wiped on reload | Switched to `storage.local`, cleared on `runtime.onStartup` |
| Tabs open before install had no track info | Manifest content scripts only run on pages loaded afterwards | Inject on `runtime.onInstalled` |
| Chillhop always showed "muted in the player" | Its decorative background video is muted | Ignore elements with the `muted` HTML attribute (`defaultMuted`) |
| Chillhop's mute never detected | Its player is a `new Audio()` kept out of the page, muted with `volume = 0`, which Chrome still reports as audible | Page-context hook on `play()`, exchanging state through DOM events |

## Test A: multi-tab capture

On the `spike/tab-capture` branch (pushed, not to be merged). Full results in [docs/spikes/tab-capture.md](../spikes/tab-capture.md).
- **Several tabs at once:** ✓, mixed in one offscreen document, with per-tab volume and crossfades.
- **Starting a capture:** only from the toolbar button (handling `action.onClicked` itself) or the context menu. **Never from the side panel**: a panel click doesn't grant `activeTab`.
- **Navigation:** a capture also survives navigating to *another site*, so the extension must stop it itself.
